# Pulsar WebHID 驱动 · 两会话轨迹复盘

个人项目的**事后复盘笔记**：为一只已停止官方支持的 **Pulsar Xlite V4 Mini** 鼠标，自己做一个"个人用途"的 **WebHID 网页驱动**——让浏览器直接与无线接收器的厂商自定义 HID 接口通信，实现与官方配置软件相当的配置功能。

过程中我先后用了两个不同的模型（DeepSeek 与 kimi-k3），它们在**同一类问题上表现差异很大**。这份文档把两段完整会话的**步骤、思考、根因与结果**整理了下来。

重点不是"驱动怎么写"，而是：

- 逆向一个被打包过的 .NET 桌面软件、拿到它的私有 HID 协议，**实际是怎样一步步收窄的**；
- 同一个顽固 bug，为什么一个模型修不掉、另一个模型靠**两次向用户提问**就定位到了根因；
- 长上下文下模型行为的退化（不再提问、把过期输入当成新鲜证据）；
- 成本与能力的对比：一次完整逆向 vs 一次顽固 bug 排障。
